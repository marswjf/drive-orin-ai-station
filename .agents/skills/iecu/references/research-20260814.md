## 一、torch / py3.10 路线（已采纳施工）

- **现成轮子确认不存在**：cp310 + CUDA≤12.1 + sm_87 + glibc≤2.31 的 torch 全网没有。
  jetson-ai-lab pypi 只服务 JetPack 6（cu126）/7（cu13x），JP5 线被明确排除（NVIDIA
  员工原话）；官方 JP5 只有 cp38 的 2.1.0a0；Qengineering 止步 py3.6/3.8；
  conda-forge 有专门的 tegra 变体且真为 sm_87 编译（PR #496），但绑死 CUDA 12.8+。
- **jetson-containers 是源码构建的权威参照**：`packages/ml/pytorch/version.py` 给
  JetPack 5（L4T≥34，CUDA 11.4 世代）钉的版本是 **torch 2.2**；
  `packages/build/python/config.py` 把 **py3.10 明确标注"JetPack 5 + 6"**（3.11 只标 JP6）。
  build.sh 关键项：USE_CUDNN=1、TORCH_CUDA_ARCH_LIST、cpuinfo 的 ARM SVE 补丁。
- **ComfyUI 官方下限已是 py3.10**（pyproject.toml `requires-python = ">=3.10"`，
  0.33.0；2025-01-22 PR #6287 正式放弃 3.8）。依赖侧 av≥16 要 3.10（最新 18.x 要 3.11）、
  gguf 最新要 3.10、连它 pin 的 transformers 4.50.3 都要 3.9——py3.8 冻结名单只会越来越长。
- **升 py3.10 也解决不了的**：onnxruntime-gpu 与 insightface 在 PyPI **从来没有**
  aarch64 轮子（任何 Python 版本），该源码编还是要源码编。
- ★ 施工后的修正（实测推翻调研的部分）：**torch 2.2 不够**——ComfyUI 用到
  `torch.uint16/32/64`（2.3+ 的 C++ dtype，shim 不了）与 `add_safe_globals`（2.4+），
  连现役 0.32 都一样；实际目标改为 **torch 2.4.1**（其 cuda.cmake 只要求 ≥11.0，实测可配）。
  现役 py3.8 能跑的真相是 torch **2.1 原生库 + 2.4.1 Python 文件混装**，不可复刻。

## 二、stable-diffusion.cpp 备选路线（未启用，用户选定 ComfyUI 主线）

> 用户明确表态"不希望用 SD 将就，要跟 ComfyUI 生态走"，此路线归档备查。
> 适用场景：将来若要一条"装好就不会坏"的固定出图通道（脱离 Python 生态）。

- **Z-Image 官方原生支持**（2025-12-01 起，内部按 Lumina2 处理）：GGUF Q8_0 直读、
  文本编码器 Qwen3-4B safetensors 直读（`--llm` 参数）、VAE 就是 FLUX 的 ae 文件，
  官方示例即 `--cfg-scale 1.0 --steps 8 --diffusion-fa`——与本板生产配置一一对应。
  Qwen-Image / FLUX / SDXL / SD1.5 也全支持。
- 功能面对照两条生产流全绿：img2img + strength（老照片修复）、ESRGAN 是通用 RRDBNet
  实现（自动探测权重结构，.pth 直读，本板两个超分模型同族）、LoRA 可挂 GGUF 底模
  （at_runtime 模式）、euler/simple 调度齐全。
- **自带 server**：内嵌 Web UI + 三套 API（原生异步 / A1111 sdapi / **OpenAI 兼容
  `/v1/images/generations`**），接 Node 面板几乎零改造。
- 量化是**真 kernel**（GGML 家族 mmq/mmvq，含 Ampere 专属配置），不是 ComfyUI-GGUF
  那种逐层反量化；且自带 flash attention（不依赖 torch）——理论上有超过 40.1s 基线的空间。
- 缺口：无官方 aarch64 预编译（需用现成 CUDA 12.1 交叉工具链自编；ggml 子模块是
  leejet 自己的 fork，非 llama.cpp 同提交）；统一内存两个已知 issue——#1586 进程内
  热切换模型 SEGV（未修，按服务重启切模型可绕开）、#1587 VAE 缓冲不释放 OOM（已修）；
  **Orin/sm_87 无任何一手性能数据**，要用必须自测。

## 三、生态先例（支持"策展环境"策略）

- **全网没有 JetPack 5 / py3.8 跑 ComfyUI 0.3x 的先例**：dusty-nv/jetson-containers
  的 comfyui 包只发布过 JP6（r36.x）镜像；所有教程/镜像全在 py3.10 上。本板部署
  大概率是孤例（查无反例，非穷尽证明）。
- **节点包元数据里的 Python 版本声明是装饰性字段**：Comfy Registry 官方规范里
  `requires-python` 只是"推荐"，官方示例至今还写 `>=3.8`；实测四个主流包
  （Impact-Pack / was-node-suite / rgthree / KJNodes）**全都不填**。
  → "声明 3.10 实际 3.8 能跑"不是个别作者虚报，判断兼容永远靠扫语法不靠元数据。
- **冻结环境的正规做法**（可借鉴）：ComfyUI-Manager 快照（ComfyUI commit + 各节点
  commit + pip freeze）、comfy-cli 的 `comfy-lock.yaml`（与 Manager 快照格式兼容，
  另含模型 hash）、第三方 comfy-pack 的 `.cpack.zip`。核心思路一致：
  **git commit 锁定 + pip freeze + 模型哈希**。切换 py3.10 后建议启用 Manager 快照。
- 节点依赖重量分级参考：零依赖（rgthree）/ 轻依赖（KJNodes：pillow+matplotlib 级）/
  重依赖（Impact-Pack、was-node-suite：opencv+transformers+分割模型栈）。
  挑包看 requirements 的纪律不变（陷阱 54）。
