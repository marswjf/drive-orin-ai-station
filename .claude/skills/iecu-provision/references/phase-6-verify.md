| 26 | 老照片修复，非正方形输入 | 48.8 s，1425×2166 → 3328×5056，**比例 0.658 保留** |
| 27 | ControlNet 双分支 512² | **21.3 s**，采样期可用内存最低 5.20 GB |

### 出图这一项的判据要格外小心，有四种假成功

| 现象 | 真相 |
|---|---|
| `Prompt executed in 0.01 seconds` + success + 无图 | 输出节点校验失败，ComfyUI 忽略输出却照报 success |
| 队列空了但 history 查不到 | 进程中途被 SIGKILL（内存打爆） |
| 第二次跑快得离谱（3 s）且有文件名 | **提示词缓存命中，根本没重新生成**。判据是文件名——没变就是缓存 |
| 前端不飘红 | 只说明节点类型注册了，不说明能跑通 |

所以第 24~27 项**每次必须换种子**，并核对输出图的尺寸与像素标准差
（标准差接近 0 说明是纯色图，等于没生成）。

## 6.6 已知的、不算故障的

新板子上也会看到这些，都是基线板一样的状态：

| 现象 | 说明 |
|---|---|
| `PatchTritonVAE` 导入失败 | aarch64 上没有 triton。KJNodes 的其余节点正常 |
| Crystools 报 `Could not init pynvml` | 板上没有 NVML 共享库。GPU 监控用面板自己的实现 |
| SeedVR2 提示 SageAttention / Flash Attention / Triton 全 ❌ | 那是它自己的加速库探测，与 torch 编入的 FA 是两回事 |
| 生图模式下 tj 稳定在 88 °C | 持续计算负载的正常水位，**CPU 仍是满频、无降频**。判断降频看频率，不看温度 |
| `Dequantizing token_embd.weight` 警告 | GGUF 加载器的正常行为 |

## 6.7 验收不过怎么办

**不要跳过去切服务。** 按判据编号回到对应阶段：

```
1~5    → 阶段 1 网络
6~16   → 阶段 3 运行时（先查 LD_LIBRARY_PATH 里 cuda122 是否排在最前）
17~20  → 阶段 4 服务（先确认走的是面板不是直连）
21~27  → 阶段 5 模型 + comfyui-import skill 的三级验证
28~31  → 阶段 2 存储 与 阶段 4 服务
```
